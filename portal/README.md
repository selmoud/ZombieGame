# Экспертный портал «Коммуникации, медиа и развлечения»

Внутренний портал для сбора, проверки и выгрузки экспертных позиций по восьми
разделам доклада с горизонтом до 2036 года.

## Возможности MVP

- регистрация эксперта с согласованием администратором;
- безопасный вход по имени и паролю;
- вход по одноразовому персональному приглашению для приглашённых экспертов;
- кабинет эксперта и статусы восьми разделов;
- формы из YAML, включая повторяемые таблицы;
- автоматическое и ручное сохранение черновика;
- отправка, возврат на доработку и принятие ответа;
- комментарии администратора;
- создание эксперта и ссылки-приглашения;
- загрузка PDF, DOCX, XLSX, PNG и JPG;
- фильтры ответов и выгрузка XLSX.

## Быстрый запуск в Docker

Из каталога `portal/`:

```bash
docker compose up --build
```

Для локальной разработки с опубликованным портом PostgreSQL используйте:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

После запуска откройте [http://localhost:3000](http://localhost:3000). Миграции
и демонстрационные данные применяются автоматически.

Пароли хранятся только в виде хешей `scrypt` и никогда не отображаются
администратору. В заявке на согласование доступны только имя и компания.

Для новой установки задайте уникальные пароли администраторов длиной не менее
16 символов в `BOOTSTRAP_ADMIN_1_PASSWORD` и
`BOOTSTRAP_ADMIN_2_PASSWORD`. Seed использует их только при первом создании
учётных записей и не перезаписывает действующие пароли. Административные
демонстрационные приглашения не создаются.

Начальный пароль supervisor Владимира Кириенко задаётся аналогично через
`BOOTSTRAP_SUPERVISOR_PASSWORD` (16–128 символов). Он используется только при
первом создании учётной записи.

Приглашения одноразовые. Не публикуйте их и отзывайте неиспользованные ссылки.

## Локальная разработка

Требуются Node.js 24+, npm и Docker.

```bash
cp .env.example .env
docker compose up -d db
npm install
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

Приложение доступно на `http://localhost:3000`.

Для production задайте `PORTAL_APP_BIND_ADDRESS=127.0.0.1`, чтобы приложение
принимало трафик только через reverse proxy. База данных в основной
Compose-конфигурации не публикуется на хосте. Укажите неизменяемый
`PORTAL_RELEASE` для каждой выкладки.

Production-образ приложения содержит только standalone-сборку Next.js.
Миграции и seed выполняются отдельным одноразовым контейнером `migrate`.

Файлы в `deploy/backup` устанавливают ежедневный локальный backup с хранением
14 дней. Для защиты от потери сервера эти копии дополнительно нужно отправлять
в отдельное российское объектное хранилище.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения PostgreSQL |
| `PORTAL_DB_PASSWORD` | Пароль PostgreSQL для запуска через Docker Compose |
| `APP_URL` | Публичный адрес портала для ссылок-приглашений |
| `INVITATION_TOKEN_PEPPER` | Секрет HMAC для хеширования приглашений |
| `MAX_BOT_TOKEN` | Токен чат-бота MAX; хранится только в runtime-окружении |
| `MAX_BOT_USERNAME` | Публичный ник чат-бота MAX без `@` |
| `MAX_WEBHOOK_SECRET` | Секрет проверки webhook-запросов MAX |
| `MAX_WORKER_SECRET` | Секрет внутреннего обработчика очереди уведомлений |
| `MAX_LINK_TOKEN_PEPPER` | Секрет HMAC для одноразовых ссылок привязки MAX |
| `BOOTSTRAP_ADMIN_1_PASSWORD` | Начальный пароль первого администратора только для новой БД |
| `BOOTSTRAP_ADMIN_2_PASSWORD` | Начальный пароль второго администратора только для новой БД |
| `BOOTSTRAP_SUPERVISOR_PASSWORD` | Начальный пароль supervisor Владимира Кириенко только при первом создании |
| `ALLOW_FUNCTIONAL_TEST_RESET` | Явное подтверждение разрушительного сброса тестовых данных |
| `FUNCTIONAL_TEST_PASSWORD_SECRET` | Секрет для паролей синтетических экспертов |
| `UPLOAD_DIR` | Каталог закрытого файлового хранилища |
| `MAX_UPLOAD_SIZE_MB` | Максимальный размер одного файла |

В production замените `INVITATION_TOKEN_PEPPER`, используйте TLS и перенесите
вложения в закрытое S3-совместимое хранилище с антивирусной проверкой.

## Структура

```text
app/                 страницы, Server Actions и Route Handlers
components/          оболочка кабинета и динамическая форма
lib/                 авторизация, БД, валидация, YAML и XLSX
modules/             восемь версионируемых YAML-модулей
prisma/              схема, миграции и seed
tests/               модульные тесты
```

Структура вопросов не зашита в интерфейс. Команда `npm run db:seed` проверяет
YAML и публикует версии модулей в PostgreSQL. Назначение эксперта сохраняет
конкретную версию, поэтому будущие изменения вопросов не повреждают старые
ответы.

Архитектурные решения подробно описаны в
[`../docs/architecture.md`](../docs/architecture.md).
